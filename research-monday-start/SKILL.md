# 科研周一启动

把分散的科研记录整理为可核查的状态快照、本周优先级、周一三项任务和首项任务的 25 分钟开工包。

## 1. 确定时间范围与材料

1. 按用户本地时区计算并写明确切日期：
   - 上周：上一自然周的周一至周日；
   - 本周：当前自然周的周一至周日。
2. 读取当前对话中已提供的材料、当前项目内与任务有关的文件，以及用户已授权且当前可访问的任务或日历来源。
3. 优先检查：
   - 上周工作记录、任务清单和未完成事项；
   - 正在修改的论文、导师或审稿意见；
   - 实验记录、模拟日志、运行状态和数据处理记录；
   - 文献阅读记录；
   - 本周截止日期、会议和交付要求。
4. 先列出实际读取的材料及日期覆盖范围。不要声称读取过不可访问、未提供或不存在的来源。
5. 若完全没有足以恢复进度的材料，暂停生成计划，只向用户索取最多三类关键材料：上周记录、当前任务文件、本周截止日期或会议。若材料不完整但仍可工作，继续生成部分结果，并明确标出缺口。

## 2. 使用统一证据标签

为每项进度、任务、日期和判断标注以下一种状态：

- **已确认**：由文件、日志、消息、日历记录或用户明确陈述直接支持。附简短依据或来源。
- **合理推断**：从已确认信息推导而来。说明推断依据，不把它写成事实。
- **待核实**：信息缺失、来源冲突、日期不清或无法访问。写明需要核实的内容。

遵守以下边界：

- 不把“未记录”当作“未完成”，也不把计划运行当作已经完成。
- 不编造完成进度、实验数据、模拟结果、参考文献、DOI、会议或截止日期。
- 不根据文件修改时间单独判断工作已经完成。
- 遇到来源冲突时并列冲突内容，标为“待核实”，不要自行选择一个版本。
- 使用确切日期，避免只写“明天”“周五”或“月底”。

## 3. 恢复上周科研状态

按下列顺序汇总：

1. 上周已经完成的成果；
2. 尚未完成或中断的事项；
3. 失败的实验、模拟或处理任务，并写明已知失败原因；
4. 等待回复、审批、数据、设备或他人输入的事项；
5. 需要用户确认的问题；
6. 分别总结论文、实验、模拟和文献阅读进度。没有证据的类别写“暂无可核实记录”。

区分“动作”和“成果”。例如，将“修改论文”具体化为可检查的成果，如“完成第 3.2 节修订并回应意见 4”。

## 4. 检查本周关键节点

按时间顺序列出本周的截止日期、会议和交付任务。每项写明：

- 确切日期和时间；
- 事项或交付成果；
- 当前准备状态；
- 前置依赖或风险；
- 证据标签与来源。

若没有可核实的日历或截止日期来源，明确写“本周关键节点尚未核实”，不要写“本周无安排”。

## 5. 排定本周优先级

综合以下因素排序：

1. 临近且明确的外部截止日期或会议；
2. 会阻塞后续研究的关键路径任务；
3. 失败风险、重跑成本或等待时间较高的实验与模拟；
4. 对当前交付成果贡献最大的论文、分析或汇报任务；
5. 可以快速解除阻碍的确认、沟通或检查事项。

分为：

- **P0 本周必须完成**；
- **P1 本周应推进**；
- **P2 可以延后**。

每项写明优先级理由和可验证的完成标准。证据不足时保留“待核实”，不要为了凑满分类而新增任务。

## 6. 只安排周一三项任务

从本周清单中选择最多三项周一任务，并按执行顺序排列。每项包含：

- 任务名称；
- 选择理由；
- 预计用时；
- 所需文件、数据、设备或回复；
- 当天可交付成果；
- 完成标准；
- 证据标签。

优先选择能够恢复上下文、解除阻碍或形成最小可交付成果的任务。若可靠信息只支持一至两项，就只安排一至两项。

## 7. 为第一项任务生成 25 分钟开工包

开工包必须可以立即执行，并包含：

1. **本轮目标**：25 分钟内完成的单一小目标；
2. **需要打开的内容**：具体文件、记录、软件或页面；
3. **第一个动作**：两分钟内可以开始的明确动作；
4. **时间分配**：0–5、5–20、20–25 分钟分别做什么；
5. **最小成果**：本轮结束时必须留下的可见产物；
6. **完成检查**：如何确认本轮已完成；
7. **下一步**：完成后最自然的后续动作。

不要把 25 分钟用于继续扩展周计划。若第一项任务仍被外部条件阻塞，将开工包改为解除该阻碍的最小动作。

## 输出格式

按以下固定顺序输出，保持简洁：

1. **时间范围与资料覆盖**
2. **上周科研状态快照**
3. **失败、等待与待确认事项**
4. **本周截止日期、会议与交付**
5. **本周优先级：P0 / P1 / P2**
6. **周一任务：最多三项**
7. **第一项任务的 25 分钟开工包**
8. **仍需用户确认的问题**

在结尾只提出会改变优先级或阻止第一项任务启动的问题，最多三个。
